# Project Views

## Purpose

Define the standard project views used to visualize and manage work throughout the product development lifecycle.

## Scope

This document defines the standard project views adopted by the Product Development Playbook.

The views are independent of any specific project management platform and may be implemented using boards, tables, roadmaps, timelines, or equivalent visualization mechanisms.

## Conceptual Model

The Product Development Playbook distinguishes between **View Types** and **View Purposes**.

A View Type defines how work items are visualized.

A View Purpose defines why a particular view exists and how it supports project management.

Different project management platforms may implement the same View Type differently while preserving its intended purpose.

## View Types

The Product Development Playbook recognizes different visualization mechanisms that may be provided by project management platforms.

Standard view types include:

- Board
- Table
- Timeline
- Roadmap
- Calendar

## View Purposes

Each project view serves one or more management purposes.

The standard purposes are:

- Operational
- Planning
- Reporting
- Strategic

## View Mapping

| View Type | Typical Purpose |
| ---------- | --------------- |
| Board | Operational |
| Table | Planning, Reporting |
| Timeline | Planning, Strategic |
| Roadmap | Strategic |
| Calendar | Operational, Planning |

## View Scope

Operational and planning views should display work items rather than pull requests.

When implemented in GitHub Projects, views intended to manage work should exclude pull requests unless explicitly required by the view's purpose.
