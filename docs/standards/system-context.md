# System Context

## Purpose

Define the boundary between a product system, its relevant actors, and external systems.

## Scope

This standard is independent of diagram notation, architecture framework, and implementation technology.

## Definition

A System Context identifies the system under consideration, the actors and external systems that interact with it, the material relationships between them, and the boundary assumed by an architecture decision.

## Rules

A System Context MUST identify the decision scope, system boundary, relevant actors, external systems, and material interactions or dependencies. It SHOULD distinguish facts, assumptions, and unresolved interfaces.

It MAY be represented by a diagram, table, model, or narrative. It does not prescribe internal components, deployment topology, or implementation details.
