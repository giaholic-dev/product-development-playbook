# Standards Relationship Map

## Purpose

Show the principal ownership and dependency relationships among the Playbook standards without duplicating their rules.

## Scope

This map covers principal ownership and dependency relationships among published Playbook standards. It does not define their detailed rules or create additional dependencies.

## Core relationships

| Concern | Governing standard | Key related standards |
| --- | --- | --- |
| Repository governance | [Repository Standards](repository-standards.md) | Branch Workflow, Code Review, Definition of Ready, Definition of Done |
| Roles and actor assignment | [Roles and Actor Assignment Standard](roles-and-actor-assignment.md) | Definition of Ready, Definition of Done, AI Collaboration Standard, Security, Privacy, and Data Governance Standard |
| Work classification | [Work Item Taxonomy](work-item-taxonomy.md) | Work Item Types, Project Views, Repository Project Field Standard |
| Vocabulary and evidence | [Terminology Standard](terminology-standard.md) | Glossary, Artifact Standard, Documentation Style Guide |
| Documentation navigation | [Documentation Information Architecture](documentation-information-architecture.md) | Documentation Navigation Standard, Standards Index, Artifact Catalog |
| Product decisions | [Product Vision](product-vision.md) | Problem Statement, Users, Outcomes, Product Scope, Product Backlog |
| Experience decisions | [UX Vision](ux-vision.md) | User Journey, Personas, User Flows, UX Validation |
| Architecture decisions | [Architecture Vision](architecture-vision.md) | System Context, Architecture Decision Records, Architecture Artifacts |
| Delivery and release | [Release Strategy](release-strategy.md) | Versioning, Release Notes, Deployment Strategy, Rollback Strategy |
| Sustained operation | [Maintenance Phase](../lifecycle/07-maintenance.md) | Incident Management, Bug Management, Technical Debt Management, Product Monitoring |

## Use

Start with the standard governing the concern. Follow related standards when their distinct responsibility applies; do not infer that a related link transfers ownership.
