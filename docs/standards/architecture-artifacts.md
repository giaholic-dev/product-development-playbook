# Architecture Artifacts

## Purpose

Define how a project selects and manages records that evidence architecture decisions without requiring a fixed set of technical deliverables.

## Scope

This standard applies to architecture artifacts and delegates categories and subtypes to the Artifact Standard.

## Rules

An architecture artifact MUST identify its decision or evidence purpose, scope, owner, and relationship to the work item or decision it supports. It MUST distinguish current, superseded, planned, and historical state.

A project MAY retain an architecture vision, system context, ADR, high-level architecture, component architecture, data model, API design, risk record, specification, or another appropriate artifact. It retains only artifacts needed for traceability, collaboration, validation, or later lifecycle decisions.

Categories and subtypes follow the [Artifact Standard](artifact-standard.md). An artifact is not mandatory merely because it is a common architecture practice.
