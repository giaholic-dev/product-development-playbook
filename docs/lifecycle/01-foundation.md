# 01 — Foundation

## Purpose

Establish a fully configured development and governance environment so product development can begin without further infrastructure or process decisions.

## Inputs

- A decision to start a new product.
- An initial product idea or concept.
- An active organization or account on the code hosting platform.

## Activities

- **F1 Repository Setup:** Initialize the main repository with proper visibility, permissions, and structure.
- **F2 Repository Standards:** Define directory layout, naming conventions, branch strategies, and commit conventions.
- **F3 Governance:** Configure the project's governance model, tracking system, planning artifacts, and delivery milestones.
- **F4 Workflow:** Define the end-to-end development lifecycle and review gates.
- **F5 Documentation:** Establish the documentation architecture, writing standards, and root navigation.

## Outputs

- An operational development environment.
- Established governance and tracking model.
- Documented engineering standards and workflows.
- A repeatable, ready-to-use project foundation.

## Definition of Done

The Foundation phase is complete when:

- The repository is operational.
- Governance is configured.
- Documentation architecture exists.
- Development standards are documented.
- The team or builder can begin Product without creating new process decisions.

## Exit Criteria

The Product phase can begin without blocking questions regarding infrastructure, governance, documentation, or workflow.

## Artifacts

- Repository
- `README.md`
- Repository Standards
- Work Item Taxonomy
- Work Item Types
- Project Views
- GitHub Project
- Workflow Specification
