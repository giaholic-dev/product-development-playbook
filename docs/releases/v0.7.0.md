## Changes since v0.6.0

- Retain committed repository source bytes, tracked path/object/mode identity, protected-file dispositions and hashes. Dirty working files are not attributed to the selected commit; symlinks remain inert. Required missing source, gitlink/LFS content and changed source identity fail explicitly.
- Preserve PR conversations, review submissions and inline comments/replies as distinct evidence, with reviewed-commit/review/reply identities and per-PR traversal observations. Review history is not inferred current approval.
- Retain Project field definitions and typed scalar/planning/organization values, completed iterations, supported built-in relationships, independent item/value/nested pagination and explicit present/unset/inapplicable/redacted dispositions.
- Retain computed built-in metadata with direct-null observations and provenance: separate item/content dates, nullable closure, parent reference and provider progress summary. The manifest explicitly excludes rendered-value reconstruction and descendant-list claims.
- Derive manifest completeness from required collection/source/replay/relationship evidence; inventory payload SHA-256/sizes and verify exact ZIP bytes before publication. New runs never overwrite previous outputs; current-run failure rolls back publication.
- Follow validated repository next links that combine page and opaque after cursors; reject changed targets/filters, repeated/disappearing cursors and unknown required types. Issue-field identity uses Node rather than an unsupported interface field. Historical supported query versions remain replayable unchanged.

## Adopter actions and compatibility

1. Preserve the previous immutable baseline and old audit packages. Compare applicable sources and record the upgrade decision under the [upgrade guide](../practices/playbook-upgrade-guide.md).
2. If using the exporter, provide Git, gh, jq and Python 3.12 or later, with already-authorized read access to the selected repository and Project. Review source sensitivity, data scope, destination and retention before explicitly enabling the run. No expanded permission is granted by these notes.
3. Keep schema-1 packages as limited historical evidence. They cannot be relabeled or converted into complete schema-2 evidence; obtain new coverage through a fresh authorized export. The new verifier supports the documented tool 2.0.0–2.1.0 / child-evidence versions without modifying old bytes.
4. Use the [coverage contract](../practices/audit-package-contract.md) and manifest dispositions/limits when interpreting results. Counts are not approvals, product execution, governance certification or complete inaccessible history.

No new product-runtime environment obligation, role, adoption artifact or software dependency for ordinary Playbook reading is introduced. Existing environment and standards obligations remain those of v0.6.0; stateful changes require the separate v0.8.0 assessment.

## Limits, support and recovery

Completeness is relative to authorized observable source and provider records over a UTC interval, not an atomic snapshot or exhaustive historical certification. The actual reviews were COMMENTED; positive inline, approval/dismissal/supersession and absent Project types have synthetic coverage only. The package does not certify provider administration, branch protections, credentials, inaccessible/deleted evidence, current approval, rendered computed columns, or full issue hierarchy. Optional Discussions remain excluded unless explicitly selected and successfully collected. Bounded secret checks do not guarantee secret-free content. The private local validation package is not a release attachment.

Report concrete defects through [repository issues](https://github.com/giaholic-dev/product-development-playbook/issues), naming the selected commit, tool/schema and affected observations without exposing credentials or private bodies. Owner @giaholic reassesses material API, source-policy, permission and coverage changes. Preserve the prior tag/package and choose a recorded prior-baseline or corrective-release disposition; never rewrite an immutable published release or claim missing evidence existed. This is methodology/tool recovery, not production-data restoration.
